[ 1. สรุปรายละเอียดและวัตถุประสงค์ของโปรเจกต์ (PROJECT OVERVIEW & PURPOSE) ]
--------------------------------------------------------------------------------
โปรเจกต์นี้คือ: ระบบเว็บแอปพลิเคชันอีคอมเมิร์ซแบบครบวงจร (Fullstack E-Commerce Web Application)
ออกแบบมาสำหรับเป็นระบบร้านค้าออนไลน์ รองรับการขายสินค้าทั่วไป, สินค้าไอที, หรือดอกไม้/ของขวัญ พร้อมระบบหลังบ้านสำหรับผู้ดูแลระบบ (Admin Dashboard)

โครงสร้างสถาปัตยกรรมของโปรเจกต์ แบ่งออกเป็น 3 ส่วนหลัก:

1. CLIENT (หน้าร้านสำหรับลูกค้า / Frontend Storefront)
   - เทคโนโลยี: React 18 (Vite 5), TailwindCSS 3, Material UI (MUI v6), React Router DOM v7
   - ฟีเจอร์หลัก:
     * แสดงผลสินค้า, หมวดหมู่, สไลด์หน้าแรก (Home Slides), แบนเนอร์ (Banners V1/List2), บล็อกข่าวสาร
     * ระบบตะกร้าสินค้า (Cart Management) และ รายการโปรด (Wishlist / MyList)
     * ระบบที่อยู่จัดส่ง (Address Management) และ โปรไฟล์ผู้ใช้งาน
     * ระบบชำระเงิน (Checkout System): รองรับ Stripe (Card & PromptPay)
     * ระบบล็อกอิน/สมัครสมาชิก: JWT Authentication + Firebase (Google OAuth Login)
     * ระบบเปลี่ยนภาษา (i18n): รองรับ TH / EN

2. ADMIN (ระบบจัดการหลังบ้านสำหรับผู้ดูแล / Admin Dashboard)
   - เทคโนโลยี: React 18 (Vite 6), Material UI v6, TailwindCSS 3, Recharts
   - ฟีเจอร์หลัก:
     * สรุปภาพรวมและสถิติยอดขาย (Dashboard Analytics)
     * จัดการสินค้า (Product CRUD), หมวดหมู่สินค้า (Category CRUD)
     * จัดการสไลด์หน้าแรก, แบนเนอร์, โลโก้เว็บไซต์, และ บล็อก
     * จัดการคำสั่งซื้อ (Order Management) และสถานะจัดส่ง
     * จัดการการตั้งค่าชำระเงิน (Payment Gateway Settings)

3. SERVER (ระบบหลังบ้าน API / Backend Server)
   - เทคโนโลยี: Node.js, Express.js (ES Modules Syntax: import/export)
   - ฐานข้อมูล: MongoDB Atlas (เชื่อมต่อผ่าน Mongoose ORM v8)
   - ระบบความปลอดภัย (Security Features):
     * JSON Web Token (JWT) + HttpOnly Cookies (Access & Refresh Token)
     * Mongoose pre-save hook เข้ารหัสรหัสผ่านด้วย bcryptjs อัตโนมัติ (ป้องกัน Double Encryption)
     * Secure Hashed OTP สุ่มด้วย crypto.randomInt
     * Auth & Admin Role-Based Middleware สำหรับป้องกัน Admin API Routes
     * Rate Limiting กัน Brute Force Attack และ NoSQL Input Sanitization
   - การจัดการรูปภาพ: Cloudinary API ร่วมกับ Multer Middleware
   - ระบบชำระเงิน: Stripe Node.js SDK (รองรับ Stripe Test & Live Mode)
   - ระบบส่งอีเมล: Nodemailer (SMTP)

[ 2. ประมาณการงบประมาณภายนอก (EXTERNAL API & SERVICE BUDGET COST BREAKDOWN) ]
--------------------------------------------------------------------------------

1. MongoDB Atlas (ฐานข้อมูล NoSQL Cloud)
   - [สายฟรี] M0 Free Tier: 0 บาท / เดือน (ให้พื้นที่ 512 MB, Shared RAM/CPU, 100 Connections) -> เพียงพอสำหรับเริ่มต้น
   - [ขยับขยาย] Shared Tier (M2 / M5): ~$9 - $25 / เดือน (ประมาณ 320 - 900 บาท / เดือน) -> พื้นที่ 2 GB - 5 GB
   - [ระดับธุรกิจ] Dedicated Cluster (M10): ~$57 / เดือนขึ้นไป (ประมาณ 2,000+ บาท / เดือน) -> สำหรับข้อมูลขนาดใหญ่ ทราฟฟิกสูง

2. Cloudinary (ระบบจัดเก็บและปรับแต่งรูปภาพ Cloud)
   - [สายฟรี] Free Plan: 0 บาท / เดือน (ให้ 25 Credits/เดือน ~25,000 รูปภาพ หรือ 25 GB Bandwidth)
   - [ขยับขยาย] Plus Plan: ~$89 / เดือน (ประมาณ 3,150 บาท / เดือน) -> สำหรับ 225 Credits
   - [ทางเลือกประหยัดเมื่อภาพเยอะ]: สามารถย้ายไปใช้ AWS S3 (~$0.023/GB หรือ 100-300 บาท/เดือน) หรือ BunnyCDN

3. Firebase Authentication (Google OAuth Login)
   - [สายฟรี] Spark Plan: 0 บาท / เดือน (ฟรีตลอดชีพสำหรับ Google OAuth และ Phone Auth ฟรี 50,000 MAU/เดือน)
   - [ขยับขยาย] Blaze Plan (Pay-as-you-go): คิดตามปริมาณจริงเกิน 50,000 MAU (ผู้ใช้ทั่วไปใช้งานฟรี 100%)

4. Stripe Payment Gateway (ระบบรับชำระเงินผ่านบัตร & PromptPay)
   - ค่าแรกเข้า / ค่ารายเดือน: 0 บาท (ไม่มีค่าบริการรายเดือน)
   - ค่าธรรมเนียมต่อรายการ: คิดเฉพาะเมื่อมีออเดอร์ชำระเงินสำเร็จ
     * ค่าธรรมเนียม Stripe Thailand: ~3.4% + 10 THB ต่อรายการสำเร็จ
   - *หมายเหตุ*: ในช่วงพัฒนา (Dev/Test Mode) สามารถทดสอบชำระเงินฟรี 100% ไม่เสียเงินแม้แต่บาทเดียว

5. Nodemailer (ระบบส่งอีเมลแจ้งเตือน / OTP)
   - [สายฟรี] Gmail SMTP: 0 บาท / เดือน (ใช้ App Password จำกัด 500 ฉบับ/วัน)
   - [ขยับขยาย] Resend / SendGrid / Mailgun: ฟรี 3,000 ฉบับ/เดือน (หากใช้เยอะประมาณ $20/เดือน หรือ ~700 บาท)

[ 5. ขั้นตอนการ DEPLOY ระบบจริง (STEP-BY-STEP DEPLOYMENT GUIDE) ]
--------------------------------------------------------------------------------

ขั้นตอนที่ 1: เตรียม Environment Variables ใน server/.env
ในไฟล์ server/.env ให้แน่ใจว่ามี Key ต่างๆ ครบถ้วน โดยเฉพาะ Stripe Keys:
--------------------------------------------------------------------------------
PORT=8000
MONGODB_URI=<YOUR_MONGODB_ATLAS_URI>
JSON_WEB_TOKEN_SECRET_KEY=<YOUR_JWT_SECRET>
SECRET_KEY_ACCESS_TOKEN=<YOUR_ACCESS_SECRET>
SECRET_KEY_REFRESH_TOKEN=<YOUR_REFRESH_SECRET>

cloudinary_Config_Cloud_Name=<YOUR_CLOUDINARY_NAME>
cloudinary_Config_api_key=<YOUR_CLOUDINARY_API_KEY>
cloudinary_Config_api_secret=<YOUR_CLOUDINARY_API_SECRET>

# Stripe API Keys (เว้นไว้ใส่ภายหลัง หรือใส่ sk_test_... / pk_test_... สำหรับ Dev Test)
STRIPE_SECRET_KEY=
STRIPE_PUBLISHABLE_KEY=
STRIPE_WEBHOOK_SECRET=
--------------------------------------------------------------------------------

ขั้นตอนที่ 2: Deploy Backend Server (Render.com)
1. Push โค้ดโปรเจกต์ขึ้น GitHub
2. เข้า Render.com -> New -> Web Service -> เลือก Repository
3. ตั้งค่า:
   - Root Directory: `server`
   - Build Command: `npm install`
   - Start Command: `npm start`
4. ใส่ Environment Variables ใน Render Dashboard ตามรายการใน server/.env
5. กด Deploy -> จะได้ Backend URL เช่น `https://my-shop-api.onrender.com`

ขั้นตอนที่ 3: Deploy Frontend Client (หน้าร้าน) บน Vercel.com
1. เข้า Vercel.com -> Add New Project -> เลือก Repository เดียวกัน
2. ตั้งค่า Project:
   - Framework Preset: Vite
   - Root Directory: `client`
   - Build Command: `npm run build`
   - Output Directory: `dist`
3. ใส่ Environment Variable:
   - `VITE_API_URL` = `https://my-shop-api.onrender.com`
   - `VITE_STRIPE_PUBLISHABLE_KEY` = `pk_test_...` (หรือ pk_live_...)
4. กด Deploy -> จะได้ URL เช่น `https://my-shop.vercel.app`

ขั้นตอนที่ 4: Deploy Frontend Admin (หลังบ้าน) บน Vercel.com
1. กด Add New Project ใน Vercel อีกครั้ง -> เลือก Repository เดิม
2. ตั้งค่า Project:
   - Root Directory: `admin`
   - Build Command: `npm run build`
   - Output Directory: `dist`
3. ใส่ Environment Variable:
   - `VITE_API_URL` = `https://my-shop-api.onrender.com`
4. กด Deploy -> จะได้ URL เช่น `https://my-shop-admin.vercel.app`

ขั้นตอนที่ 5: ตั้งค่า Domain และ CORS Security
1. หากซื้อโดเมนตนเอง (เช่น `myshop.com`):
   - เข้า Vercel -> Settings -> Domains -> เพิ่ม `myshop.com` และปรับ CNAME/DNS ตาม Vercel แนะนำ
2. ใน `server/index.js` หรือ Environment Variable:
   - กำหนด `FRONTEND_URL` = `https://myshop.vercel.app`
   - กำหนด `ADMIN_URL` = `https://myshop-admin.vercel.app`

[ 6. เกร็ดความรู้และการตั้งค่าความปลอดภัยเพิ่มเติม (SECURITY & INTEGRATION DETAILS) ]
--------------------------------------------------------------------------------

1. ความเข้าใจเรื่อง Stripe Keys (การแยกฝั่งหน้าบ้าน vs หลังบ้าน):
   - ฝั่ง Client (client/.env):
     * ใส่เฉพาะ `VITE_STRIPE_PUBLISHABLE_KEY=pk_test_...` เท่านั้น
     * ห้ามใส่ Secret Key เด็ดขาด เพื่อป้องกันไม่ให้ถูก Inspect F12 ใน Browser ขโมยคีย์ไปแฮกบัญชี
   - ฝั่ง Server (server/.env):
     * `STRIPE_SECRET_KEY=sk_test_...` (ใช้สำหรับสร้าง PaymentIntent และตัดเงิน)
     * `STRIPE_PUBLISHABLE_KEY=pk_test_...`
     * `STRIPE_WEBHOOK_SECRET=whsec_...` (ใช้สำหรับยืนยันลายเซ็นดิจิทัลการแจ้งเตือนชำระเงิน)

2. STRIPE_WEBHOOK_SECRET คืออะไร? หาจากไหน? จำเป็นต้องใช้มั้ย?:
   - คืออะไร: รหัสลับยืนยันความปลอดภัย (`whsec_...`) ที่ Stripe มอบให้เซิร์ฟเวอร์เรา เพื่อยืนยันว่าสัญญาณที่ยิงเข้ามาบอกสถานะ "ชำระเงินสำเร็จ" ส่งมาจาก Stripe จริงๆ
   - หาจากไหน: ล็อกอิน Stripe Dashboard -> Developers -> Webhooks -> Add endpoint (`https://<YOUR-API-DOMAIN>/api/stripe/webhook`) -> เลือก Event `payment_intent.succeeded` -> ก๊อปปี้ Signing secret
   - จำเป็นมั้ย:
     * Dev Mode: ไม่จำเป็นต้องใส่ก็ได้ (เว้นว่างไว้ได้) ระบบชำระเงินทดสอบยังทำงานได้ปกติ
     * Production: แนะนำให้ใส่เป็นอย่างยิ่งโดยเฉพาะชำระผ่าน PromptPay เพื่อให้อัปเดตสถานะออเดอร์ใน DB และส่งอีเมลยืนยันอัตโนมัติ

3. การตั้งค่า MongoDB Atlas Network Access (0.0.0.0/0):
   - Deploy บน Render.com / PaaS: ให้คง `0.0.0.0/0` (Allow Access from Anywhere) ไว้ตามเดิม เพราะเซิร์ฟเวอร์ Render ใช้ Dynamic IP Pool หากไปจำกัด IP จะทำให้เซิร์ฟเวอร์ต่อ DB ไม่ได้ โดยความปลอดภัยยังคงสูงเพราะถูกล็อคด้วย DB Username/Password และ SSL Encryption
   - Deploy บน VPS (DigitalOcean / Hetzner): สามารถลบ `0.0.0.0/0` ออก แล้วระบุเฉพาะ Static IP ของเครื่อง VPS เพื่อเพิ่มความปลอดภัยระดับ Firewall
